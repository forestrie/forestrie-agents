# Cursor harness

Canonical agent files live in this repo as plain markdown. Cursor-specific
`.cursor/` paths in a project repo are **adapters**, not sources of truth.

## Skills — the shared format

Cursor loads skills from all of these, and treats `SKILL.md` directories the
same way Claude Code does:

| Path | Notes |
|------|-------|
| `.cursor/skills/<name>/` | project |
| `~/.cursor/skills/<name>/` | global |
| `.agents/skills/<name>/` | project, [Agent Skills](https://agentskills.io) standard |
| `~/.agents/skills/<name>/` | global, same standard |
| `.claude/skills/`, `~/.claude/skills/` | compatibility paths — Cursor reads these too |

The last row is the important one: **one `.claude/skills/` directory serves
Claude Code and Cursor at once.**
[`bin/forestrie-agents-sync`](../bin/forestrie-agents-sync) writes all of them
anyway, since the symlinks are free and it removes any dependence on which
compatibility path a given Cursor build honours.

## Install

From any Forestrie repo:

```bash
~/Dev/personal/forestrie/forestrie-agents/bin/forestrie-agents-sync
```

Produces, per repo:

```text
.claude/skills/<name>      -> forestrie-agents/workflow/skills/<name>   # Claude Code + Cursor
.cursor/skills/<name>      -> same target                               # Cursor, native path
.agents/skills/<name>      -> same target                               # Cursor + pi, open standard
.cursor/commands/<name>.md -> that skill's SKILL.md                     # Cursor's older command menu
```

all excluded via `.git/info/exclude`, so they never show up in `git status` or
get committed. Re-run it after pulling this repo; add `--prune` to drop links
for skills that have been removed.

The `.cursor/commands/` links are belt-and-braces for Cursor builds that
predate skills support. They point at the same `SKILL.md`, so there is nothing
to keep in sync.

## Recommended layout (per repo)

```text
AGENTS.md             # thin router at repo root (Forestrie default today)
forest/agents/
  skills/             # optional repo overlay — shadows team + vendored skills
  rules/              # optional repo overlay
.claude/skills/       # generated by forestrie-agents-sync
.cursor/
  skills/             # generated
  commands/           # generated
  rules/              # repo-specific overlay rules only
.agents/skills/       # generated
```

## Rules

Rules are skills too — `workflow/rules/<name>/SKILL.md`, annotated with
`user-invocable: false` and, where file-type scoped, `paths:`. They install
with everything else. Cursor reads them from `.claude/skills/` /
`.cursor/skills/` like any other skill.

For Cursor's **native** glob scoping, generate `.mdc` shims:

```bash
~/Dev/personal/forestrie/forestrie-agents/bin/forestrie-agents-sync --cursor-rules
```

`paths:` maps onto Cursor's `globs:`, and the shim body is a one-line pointer
at the same `SKILL.md` — nothing is duplicated, so nothing can drift.

**Safe by construction:** the generator never overwrites a `.mdc` it did not
write. canopy, univocity, mandate, and curator each track hand-written
`.cursor/rules/*.mdc` duplicating [workflow/rules/](../workflow/rules/); those
files are skipped with a warning, so you can adopt this before retiring them.
Generated files are excluded individually via `.git/info/exclude`, so a repo
that tracks `.cursor/rules/` stays clean.

Retiring a hand-written copy is then a one-line delete plus a re-run.
